# Member Recall Skill (生产级交互式会员召回)

本 skill 引导运营团队完成一个严谨的、分阶段的生产级会员召回任务。

---

## 输入 (Input)

### 用户指令

| 类型 | 示例 | 说明 |
|------|------|------|
| **启动流程** | "启动生产级会员召回策略流程" | 开始完整的5步骤召回流程 |
| **单步指导** | "步骤1要做什么", "如何做动机洞察" | 获取特定步骤的执行指导 |
| **代码执行** | "运行召回脚本", "执行匹配策略" | 执行提供的Python代码 |
| **文件生成** | "生成人群包", "输出CSV" | 生成可导入营销平台的文件 |

### 必要输入

- **会员数据CSV文件**：包含完整字段的会员数据（如 `members_data_YYYYMM.csv`）
- **API Key**：用于调用 LLM 生成动机和文案

### 会员数据字段要求

| 字段名 | 类型 | 说明 |
|--------|------|------|
| member_id | string | 会员唯一标识 |
| last_purchase_days | int | 距上次购买天数 |
| total_purchase_count | int | 累计购买次数 |
| total_spend | float | 累计消费金额 |
| coupon_usage_rate | float | 优惠券使用率 (0-1) |
| avg_order_value | float | 平均订单金额 |
| days_since_register | int | 注册至今天数 |

## 输出 (Output)

### 5步骤SOP流程

| 步骤 | 名称 | 输出 |
|------|------|------|
| **步骤0** | 初始化 | 确认API Key，导入/生成会员数据 |
| **步骤1/5** | 动机洞察 | 用户确认的动机JSON（如 A/B/C/D 四类） |
| **步骤1.5/5** | 品牌调性确认 | 品牌名称、品牌调性（高端/亲民/情感/简约） |
| **步骤2/5** | 文案创生 | 用户审核确认的文案库（按动机分类），含敏感词检测 |
| **步骤3/5** | 策略匹配 | 启发式匹配策略确认，人群包生成 |
| **步骤4/5** | 产出交付 | `ai_group_YYYYMMDD.csv`（个性化文案）和 `control_group_YYYYMMDD.csv`（通用文案） |

### 交互要点

**步骤0：初始化**
> "【步骤0/5: 初始化】请提供会员数据文件路径，或选择生成测试数据：1. 我有数据文件 (请提供路径) 2. 生成10000条测试数据"

**步骤1：动机洞察**
> "【步骤1/5: 动机洞察】已对数据摘要分析，归纳出4种核心沉睡动机，请您审核、修改或确认。"

**步骤1.5：品牌调性确认 [新增]**
> "【步骤1.5/5: 品牌调性确认】请提供以下信息：\n1. 品牌名称：____\n2. 品牌调性（单选）：A.高端奢华 B.亲民实惠 C.情感温暖 D.简约时尚"

> "【步骤2/5: 文案创生】已为每个动机生成3版不同风格文案（A.尊享感, B.利益驱动, C.情感共鸣），请挑选最终使用的文案。\n⚠️ 敏感词检测：已通过[警告:发现敏感词'最高'，建议替换为'高品质']"

> "【步骤4/5: 产出交付】已按50/50比例生成A/B测试人群包：\n- AI组：{n}人（个性化文案）\n- 对照组：{n}人（通用文案：'亲爱的会员，我们一直想念您，期待您的归来。'）\n可直接导入营销平台执行。"

## 核心原则

### 生产级标准
- **无模拟**：每一步都基于真实数据和业务逻辑
- **无假设**：所有输出都可直接用于生产环境
- **可执行**：每个步骤都有明确的操作指令

### 交互式协作
1. **分步执行**：在标记为 `--- INTERACTION REQUIRED ---` 的地方暂停
2. **清晰汇报**：向用户展示AI生成的中间结果
3. **请求确认**：明确请求用户审核、修改、确认或批准
4. **忠实执行**：只有获得明确批准后才能继续下一步

### 合规性要求
- **敏感词检测**：所有生成文案必须经过敏感词检测，违禁词需替换或警告
- **文案模板化**：避免硬编码动态数据（如具体天数、购买次数），使用通用表述或模板变量
- **A/B测试对照**：对照组使用统一通用文案，确保实验可解释

---

## 敏感词检测

### 敏感词分类

| 类别 | 示例 | 处理方式 |
|------|------|----------|
| 违禁词 | 最高、国家级、最佳、第一、顶级 | 替换为合规表述 |
| 极限词 | 唯一、首选、首家、最先进 | 警告并替换 |
| 诱导性词 | 立即抢购、过期不候、马上领取 | 警告 |
| 个人信息暗示 | 身份证、银行卡、密码、验证码 | 警告 |
| 虚假宣传 | 保证收益、无风险、100%有效 | 警告 |

### 检测流程
```
文案生成后 → 敏感词检测 → 警告提示 → 用户确认 → 导出
```

## 启发式匹配策略（冷启动）

### 用户分层规则

| 用户类型 | 判定条件 | 匹配策略 |
|----------|----------|----------|
| **高价值用户** | total_spend > 90分位 | 优先匹配"尊享感"(StyleA)文案 |
| **价格敏感用户** | coupon_usage_rate > 75% | 优先匹配"利益驱动"(StyleB)文案 |
| **其他用户** | 其余情况 | 在对应动机文案中随机匹配 |

### 匹配逻辑

```python
# 伪代码逻辑
if segment == 'HighValue':
    匹配 StyleA (Premium/尊享感)
elif segment == 'PriceSensitive':
    匹配 StyleB (Benefit/利益驱动)
else:
    随机匹配该动机的任一文案
```

### 目的

此策略旨在：
- 最大化初次尝试的效果
- 为未来ML模型收集"特征-文案-效果"数据

---

## A/B测试设计

### 设计原则

为了真正验证个性化文案的效果，A/B测试采用以下设计：

| 组别 | 文案策略 | 说明 |
|------|----------|------|
| **AI组（实验组）** | 个性化文案 | 基于用户分层（高价值/价格敏感/普通）匹配不同风格 |
| **对照组（控制组）** | 通用文案 | 所有用户收到统一的通用文案，无用户特征差异 |

### 通用文案示例
```
"亲爱的会员，我们一直想念您，期待您的归来。"
```

### 为什么需要对照组？
- 个性化文案与通用文案的对比，才能验证"个性化"的价值
- 排除"仅因为收到召回消息"而产生的效果，排除干扰因素
- 为后续ROI计算提供基准线

### 目录结构

```
member-recall/
├── SKILL.md                    # Skill定义（本文档）
├── config.json                 # 配置文件（API Key、脱敏处理等）
├── runner.py                   # 统一入口脚本
├── references/
│   ├── __init__.py
│   ├── production_crm_assistant.py  # 核心执行逻辑
│   ├── templates/              # 文案模板库
│   │   ├── copy_templates.json
│   │   └── generic_copy.json   # 通用文案模板
│   └── sensitive_words.json    # 敏感词库
├── data/                       # 数据目录（运行时生成）
└── evals/
    └── evals.json              # 评估用例
```

### 完整代码

请参考以下文件：
- `references/production_crm_assistant.py` - 核心执行逻辑
- `runner.py` - 统一入口脚本
- `config.json` - 配置文件

### 代码模块

| 模块 | 功能 |
|------|------|
| `propose_and_confirm_motivations()` | LLM生成动机初稿 → 用户确认 |
| `confirm_brand_tone()` | 品牌调性确认（新增步骤1.5） |
| `propose_and_confirm_copy()` | LLM生成文案初稿 → 用户审核确认 → 敏感词检测 |
| `check_sensitive_words()` | 敏感词检测与警告 |
| `heuristic_matching_cold_start()` | 基于规则的冷启动匹配 |
| `generate_ab_groups()` | 生成A/B测试人群包（对照组使用通用文案） |
| `run_production_flow()` | 主流程编排 |

### 运行方式

```bash
# 使用runner.py（推荐）
python runner.py --full --data members_data.csv

# 指定步骤执行
python runner.py --step 1 --data members_data.csv    # 步骤1：动机洞察
python runner.py --step 2                            # 步骤2：文案创生
python runner.py --step 4                            # 步骤4：产出交付

# 继续上次中断的流程
python runner.py --resume

# 直接调用核心模块
python production_crm_assistant.py --input_file members_data.csv --api_key YOUR_KEY --test_ratio 0.5
```
