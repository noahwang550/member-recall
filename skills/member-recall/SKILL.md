# Member Recall Skill — 生产级交互式会员召回

本 skill 引导运营团队完成一个严谨的、分阶段的生产级会员召回任务。

**你（Claude）就是执行此 skill 的大模型。** 动机洞察和文案创生由你直接生成，无需调用任何外部 API。Python 脚本仅用于确定性数据处理（CSV 读写、敏感词检测、A/B 分组）。

---

## 输入

### 必要输入

- **会员数据 CSV 文件**：包含以下必需字段

| 字段名 | 类型 | 说明 |
|--------|------|------|
| member_id | string | 会员唯一标识 |
| last_purchase_days | int | 距上次购买天数 |
| total_purchase_count | int | 累计购买次数 |
| total_spend | float | 累计消费金额 |
| coupon_usage_rate | float | 优惠券使用率 (0-1) |
| avg_order_value | float | 平均订单金额 |
| days_since_register | int | 注册至今天数 |

### 无需配置

- ~~API Key~~ — 你就是大模型，直接生成内容
- ~~环境变量~~ — 无需任何外部服务

## 执行流程

### 步骤0：初始化

**目标：** 确认数据来源

向用户提问：
> 【步骤0/5: 初始化】请提供会员数据文件路径，或选择生成测试数据：
> 1. 我有数据文件 (请提供路径)
> 2. 生成10000条测试数据

如果选择生成测试数据，执行：
```bash
python scripts/data_utils.py --action generate-test --output data/test_members.csv --num 10000
```

如果用户提供数据文件，验证字段完整性：
```bash
python scripts/data_utils.py --action profile --input <用户提供的路径>
```

如果字段缺失，告知用户缺少哪些字段并等待提供正确格式的文件。

---

### 步骤1：动机洞察

**目标：** 基于数据画像，提出有数据支撑的 4 类沉睡动机

**⚠️ 关键步骤 — 请先读取参考文档：**
读取 `references/motivation_guide.md` 获取完整的分析方法论。

**执行流程：**

1. **数据画像** — 运行：
   ```bash
   python scripts/data_utils.py --action profile --input <数据文件>
   ```

2. **自由探索** — 根据画像结果，可以进一步用 pandas 探索特定模式

3. **动机映射** — 将数据模式映射到动机原型（参考 motivation_guide.md 中的 6 大原型）

4. **提出动机** — 按以下格式向用户展示：

```
【步骤1/5: 动机洞察】数据画像分析完成，关键发现如下：

📊 基本概况
- 总会员数：{N}
- 沉睡 90-180 天：{pct}%
- 高价值用户（P90）贡献收入：{pct}%

📊 行为特征
- 优惠券使用率 >75% 的用户占比：{pct}%
- 仅购买 1-2 次的用户占比：{pct}%
- 高客单+低优惠券用户占比：{pct}%

基于以上数据，我提议以下 4 类沉睡动机：

| 动机 | 描述 | 预估占比 | 数据依据 |
|------|------|----------|----------|
| A | {动机名称} | ~{pct}% | {具体数据引用} |
| B | {动机名称} | ~{pct}% | {具体数据引用} |
| C | {动机名称} | ~{pct}% | {具体数据引用} |
| D | {动机名称} | ~{pct}% | {具体数据引用} |

请审核、修改或确认以上动机分类。
```

5. **等待确认** — 用户确认后，将最终动机保存为 JSON：
   ```json
   {
     "A": "动机描述...",
     "B": "动机描述...",
     "C": "动机描述...",
     "D": "动机描述..."
   }
   ```

### 步骤1.5：品牌调性确认

**目标：** 确认品牌名称和调性，为文案创生做准备

向用户提问：
> 【步骤1.5/5: 品牌调性确认】请提供以下信息：
> 1. 品牌名称：____
> 2. 品牌调性（单选或多选）：
>    A. 高端奢华 — 强调品质、尊贵、专属服务
>    B. 亲民实惠 — 强调性价比、优惠活动
>    C. 情感温暖 — 强调陪伴、回忆、情感连接
>    D. 简约时尚 — 强调设计感、潮流
> 3. 品牌其他特点（可选）：____

记录用户输入的品牌信息，用于步骤2的文案生成。

---

### 步骤1.7：联网调研

**目标：** 通过 WebSearch/WebFetch 获取品牌事实、行业召回实践、竞品动态和合规信息，为步骤2文案创生提供真实的事实与词汇支撑

**⚠️ 关键步骤 — 请先读取参考文档：**
读取 `references/research_guide.md` 获取完整的联网调研方法论。

**执行流程：**

1. **填充查询模板** — 从步骤1.5获取的品牌名、调性、（可选）行业，填入 research_guide.md 中四大维度的查询模板

2. **按预算执行搜索** — 遵循搜索预算（4-8次搜索，0-4次 fetch），按维度1→2→3→4顺序执行：
   - 维度1 品牌事实：2-3次搜索，获取产品线/系列名、品牌DNA、会员词汇
   - 维度2 行业召回实践：1-2次搜索，获取行业模式与激励类型
   - 维度3 竞品动态：1-2次搜索，获取竞品活动与差异化启示
   - 维度4 行业合规：0-1次搜索（美妆/食品/母婴/医疗/金融必须执行）
   - 遵守提前停止规则：维度输出字段填满即停止该维度搜索

3. **综合为调研发现报告** — 按 research_guide.md 中的报告模板整理，引用来源，标注权威性

4. **展示报告** — 以 `【步骤1.7/5: 联网调研】` 标题开头，向用户展示调研发现

5. **等待用户确认** — 用户确认后进入步骤2；用户可指出错误或补充信息，修正后再次确认

6. **降级路径** — 如遇以下情况：
   - 部分维度信息不足 → 标注"未找到足够的公开信息"，继续使用已有结果
   - 所有维度均无有效结果 → 告知用户并给出两个选项：（a）用户手动粘贴品牌事实 或（b）直接进入步骤2（不依赖调研结果）
   - WebSearch/WebFetch 工具不可用 → 同上处理

> **核心铁律：**
> - 不得编造品牌事实（产品线、会员等级等）
> - 不得复刻竞品文案句式（只提取事实与词汇，句式必须原创）

---

### 步骤2：文案创生

**目标：** 为每个确认的动机生成 3 种风格的召回文案

**⚠️ 关键步骤 — 请先读取参考文档：**
读取 `references/copywriting_guide.md` 获取完整的文案创作方法论。

**执行流程：**

1. **生成文案** — 对每个确认的动机，生成 3 种风格的文案：

| 风格 | 名称 | 核心目标 |
|------|------|----------|
| StyleA | 尊享感 | 让会员感到被重视、有特权 |
| StyleB | 利益驱动 | 用具体利益吸引回来 |
| StyleC | 情感共鸣 | 唤起情感连接和美好回忆 |

2. **文案约束：**
   - 字数：45-70 个汉字
   - 禁止硬编码动态数据（如"100+天""8次购买"）
   - 允许模板变量（如 {会员昵称}、{积分余额}）
   - 三种风格必须真正不同（不是换词游戏）
   - 符合品牌调性
   - 包含退订说明（如"回复TD退订"）
   - 文案必须优先使用调研发现中的品牌事实词汇（产品线名、会员体系词汇、品牌DNA关键词），替代泛泛的"品质""礼遇"
   - 文案不得复刻竞品或行业案例中的句子——调研结果用于事实与词汇，不用于句式

3. **生成格式** — 为每条文案提供：
   - 风格标签
   - 文案内容
   - 字数统计
   - 创作理由（为什么这样写；如果执行了步骤1.7调研，必须注明使用了哪些调研发现的事实，如"引用天气丹系列与黑卡会员词汇"）

4. **展示给用户审核：**

```
【步骤2/5: 文案创生】已为每个动机生成3版不同风格文案，请审核：

动机 A: {动机描述}

| 风格 | 文案 | 字数 | 创作理由 |
|------|------|------|----------|
| StyleA 尊享感 | {文案内容} | 62 | {理由} |
| StyleB 利益驱动 | {文案内容} | 58 | {理由} |
| StyleC 情感共鸣 | {文案内容} | 55 | {理由} |

您可以：
- 确认使用以上文案
- 修改任何一条文案
- 删除不需要的版本
- 要求重新生成
```

5. **敏感词检测** — 用户确认文案后，执行：
   ```bash
   # 先将文案保存为 JSON 文件
   python scripts/data_utils.py --action sensitive-check --copy <文案JSON文件>
   ```

   如果发现敏感词，向用户报告并请求确认：
   > ⚠️ 敏感词检测结果：
   > - [{类别}] 发现敏感词: '{词}' - 建议: {替换建议}
   >
   > 是否确认继续使用以上文案？

6. **保存最终文案库** — 格式：
   ```json
   {
     "A": {
       "A-StyleA": "文案内容...",
       "A-StyleB": "文案内容...",
       "A-StyleC": "文案内容..."
     },
     "B": { ... },
     "C": { ... },
     "D": { ... }
   }
   ```

---

### 步骤3：策略匹配

**目标：** 确认启发式匹配策略

向用户展示匹配规则：
> 【步骤3/5: 策略匹配】采用基于专家规则的"智能启发式匹配"策略：
>
> | 用户类型 | 判定条件 | 匹配文案风格 |
> |----------|----------|--------------|
> | 高价值用户 | total_spend > 90分位 | StyleA 尊享感 |
> | 价格敏感用户 | coupon_usage_rate > 75%（且非高价值） | StyleB 利益驱动 |
> | 其他用户 | 其余情况 | 随机匹配 |
>
> 优先级：高价值用户判定优先于价格敏感，避免高消费会员被降级为利益驱动文案。
>
> 是否批准执行？

用户批准后，执行匹配：
```bash
python scripts/data_utils.py --action match --input <数据文件> --copy <文案JSON> --motivations <动机JSON> --output data/matched.csv
```
> `--motivations` 可选；提供则按动机分布分配标签，否则随机分配。

### 步骤4：产出交付

**目标：** 生成 A/B 测试人群包

执行：
```bash
python scripts/data_utils.py --action ab-split --input <数据文件> --copy <文案JSON> --motivations <动机JSON> --ratio 0.5 --output data/
```

向用户报告：
> 【步骤4/5: 产出交付】已按 50/50 比例生成 A/B 测试人群包：
>
> - AI组：{n} 人 → `data/ai_group_{date}.csv`（个性化文案）
> - 对照组：{n} 人 → `data/control_group_{date}.csv`（通用文案）
>
> 对照组通用文案："亲爱的会员，我们一直想念您，期待您的归来。"
>
> 文件可直接导入营销平台执行。

## 核心原则

### 生产级标准
- **无模拟**：每一步都基于真实数据和业务逻辑
- **无假设**：所有输出都可直接用于生产环境
- **可执行**：每个步骤都有明确的操作指令

### 交互式协作
1. **分步执行**：每个步骤完成后暂停，等待用户确认
2. **清晰汇报**：向用户展示中间结果和数据依据
3. **请求确认**：明确请求用户审核、修改、确认或批准
4. **忠实执行**：只有获得明确批准后才能继续下一步

### 合规性要求
- **敏感词检测**：所有生成文案必须经过敏感词检测
- **文案模板化**：避免硬编码动态数据
- **A/B测试对照**：对照组使用统一通用文案，确保实验可解释
- **调研合规**：联网调研结果必须附来源，行业特定违禁词并入步骤2约束
